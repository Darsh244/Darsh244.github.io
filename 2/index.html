Assignment 2

1. Part 1: Polynomial Basis Function

This part implements linear basis function regression with polynomial basis functions on the Boston Housing dataset. The task is to predict the median house value (MEDV, in thousands of dollars) from the 13 town-level features. Only monomials of a single variable are used, with no cross-terms, so for a degree-$M$ model the feature vector is $$\phi(\mathbf{x}) = (1,\; x_1, x_1^2, \dots, x_1^M,\; x_2, x_2^2, \dots, x_2^M,\; \dots,\; x_{13}, \dots, x_{13}^M)$$ The first 100 points are the training set and the remaining 406 points are the test set.

1.1 Setup and Method

Normalization. Each raw feature is standardized using the training mean and standard deviation only, $$\tilde{x}_j = \frac{x_j - \mu_j^{\text{train}}}{\sigma_j^{\text{train}}}$$ and the polynomial terms are then built from $\tilde{x}_j$. The same $\mu_j, \sigma_j$ are applied to the test set. The target MEDV is not normalized, so all errors are in thousands of dollars. In the training set the feature CHAS is always $0$ ($\sigma = 0$), so its standard deviation is replaced by $1$ and the column becomes identically zero.

Unregularized fit. With design matrix $\Phi$ and targets $\mathbf{t}$, the weights are the least-squares solution $$\mathbf{w} = \arg\min_{\mathbf{w}} \|\Phi\mathbf{w} - \mathbf{t}\|_2^2 = \Phi^{+}\mathbf{t}$$ computed with numpy.linalg.lstsq (minimum-norm solution when $\Phi^T\Phi$ is singular, which happens for CHAS and for high degrees). Error metric: $\text{RMS} = \sqrt{\frac{1}{N}\sum_n (y_n - t_n)^2}$.

Feature indexing. Features are indexed from $0$, matching the assignment's convention in part (b) where the 5th feature is the average number of rooms (RM) and the 7th is the distance to employment centres (DIS). Under this convention, the single feature used in parts (c) and (d) is feature $2$, INDUS (proportion of non-retail business acres).

1.2 (a) Error versus Polynomial Degree

polynomial_regression fits degrees $1$ to $7$ on all 13 features (no regularization) and returns the training and test RMS errors. 

def polynomial_regression(X_train, t_train, X_test, t_test, max_degree=7):
    """Fit degree 1..max_degree polynomial basis regression (all features)."""
    Xn_train, Xn_test = normalize(X_train, X_test)
    train_err, test_err, weights = [], [], {}
    for d in range(1, max_degree + 1):
        Phi_train = poly_design(Xn_train, d)
        Phi_test = poly_design(Xn_test, d)
        w = fit_ls(Phi_train, t_train)
        train_err.append(rmse(Phi_train, w, t_train))
        test_err.append(rmse(Phi_test, w, t_test))
        weights[d] = w
    return train_err, test_err, weights

Comment. The training error decreases monotonically from 2.04 at degree 1 to 0.88 at degree 7, as expected because each model contains the previous one and a degree-7 model has 92 parameters for only 100 training points. The test error behaves in the opposite way: it is already 36.4 at degree 1, about 18 times the training error, and then grows by orders of magnitude to roughly $6.9\times 10^{15}$ at degree 7. This is overfitting, but the size of the blow-up is mainly caused by extrapolation. The first 100 towns cover only a narrow slice of the dataset: for example, CRIM never exceeds $1.61$ in the training set but reaches $88.98$ in the test set, which is about $229$ training standard deviations from the training mean. A degree $M$ term grows like $z^M$, so these test points produce enormous predictions, and the higher the degree the worse it gets. The training error alone would suggest picking the highest degree, but the test error shows that degree 1 is the only reasonable choice here.

Feature 5 (RM). The weight is 4.1956. The training standard deviation of RM is 0.488 rooms, so converting back to the original units gives $4.1956 / 0.488 \approx 8.59$ thousand dollars per additional room. This is reasonable: the sign is positive (more rooms means a more valuable house) and it is the largest positive weight in the model.

Feature 7 (DIS). The weight is 0.0107, which is essentially zero (0.008 thousand dollars per unit of distance in the original units). This is not what one would expect: towns closer to the employment centres should be more desirable, which would suggest a clearly negative weight. A likely explanation is collinearity within the training set: DIS is correlated with ZN ($0.60$) and NOX ($-0.48$), and these features absorb the effect that DIS would otherwise carry. With only 100 points from a small geographic area, individual weights are not very stable, so this weight should not be interpreted as saying that distance does not matter. Finally, the CHAS weight is exactly $0$ only because no training town borders the Charles River.

1.4 (c) Visualizing One Feature

To visualize the regression, only feature $2$ (INDUS) is used. polynomial_regression_1d_vis normalizes the feature with the training statistics, fits a polynomial of the requested degree, and plots the training points, the test points and the learned polynomial, evaluated on a dense grid over the full range of the data. The vertical axis is clipped to $[-20, 80]$ so the shape of the curve is visible. 

def polynomial_regression_1d_vis(X_train, t_train, X_test, t_test,
                                 degree, feature=2, ax=None):
    """Fit a degree-d polynomial to a single feature and plot it."""
    x_train, x_test = X_train[:, [feature]], X_test[:, [feature]]
    xn_train, xn_test = normalize(x_train, x_test)
    w = fit_ls(poly_design(xn_train, degree), t_train)

    # dense grid in the original units, normalized with the training stats
    lo = min(x_train.min(), x_test.min())
    hi = max(x_train.max(), x_test.max())
    grid = np.linspace(lo, hi, 400)[:, None]
    grid_n = normalize(x_train, grid)[1]
    curve = poly_design(grid_n, degree) @ w

    if ax is not None:
        ax.scatter(x_train, t_train, s=18, c="tab:blue", label="train")
        ax.scatter(x_test, t_test, s=10, c="tab:orange", alpha=0.6,
                   label="test")
        ax.plot(grid, curve, "k-", lw=2, label=f"degree {degree} fit")
        ax.set_xlabel(f"{FEATURES[feature]} (feature {feature})")
        ax.set_ylabel("MEDV ($1000s)")
        ax.set_ylim(-20, 80)
        ax.legend()
    return (rmse(poly_design(xn_train, degree), w, t_train),
            rmse(poly_design(xn_test, degree), w, t_test))

The line has a gentle negative slope (higher industrial share, lower house value) and captures the overall trend. It underfits the training points slightly (training RMS 5.24), but it is the best on the test set (test RMS 9.86), including for the test towns with INDUS far beyond the training range.

The cubic follows the training points more closely (training RMS 4.35): it falls steeply at low INDUS, flattens out near INDUS $\approx 10$, and then curves back upward. That upturn is driven by the last few training points, and beyond INDUS $\approx 15$ the curve keeps rising (to about $79$ at INDUS $= 27.7$) while the test towns there are worth $7$ to $20$, so the test RMS rises to 17.25. The extra flexibility is already being spent on the particular shape of the 100 training points.

The degree-7 polynomial oscillates through the training points (training RMS 3.99), then shoots up steeply right after INDUS $\approx 15$, where the training data ends. The test towns have INDUS up to $27.7$, well past the end of the training data, so the curve is far from them, giving a test RMS of about 29,250. This is a clear example of high-order polynomials overfitting and extrapolating badly.

1.5 (d) L2-Regularized Polynomial Regression

polynomial_regression_reg fits a degree-8 polynomial to the single feature INDUS using only the first 100 points, with the L2 penalty $$E(\mathbf{w}) = \|\Phi\mathbf{w} - \mathbf{t}\|_2^2 + \lambda \sum_{j \ge 1} w_j^2 \quad\Longrightarrow\quad \mathbf{w} = (\Phi^T\Phi + \lambda I')^{-1}\Phi^T\mathbf{t}$$ where $I'$ is the identity with its first diagonal entry set to $0$ so the bias is not penalized. For each $\lambda \in \{0, 0.01, 0.1, 1, 10, 100, 1000\}$, 10-fold cross-validation is used: the 100 points are randomly shuffled (fixed seed) into 10 folds of 10 points, and each fold is used once for validation. The normalization statistics are recomputed on the 90 training points of each fold, and the validation RMS error is averaged over the 10 folds. 

def fit_ridge(Phi, t, lam):
    """L2-regularized least squares; the bias weight is not penalized."""
    P = np.eye(Phi.shape[1])
    P[0, 0] = 0.0
    return np.linalg.solve(Phi.T @ Phi + lam * P, Phi.T @ t)


def polynomial_regression_reg(X_train, t_train, degree=8, feature=2,
                              lambdas=LAMBDAS, k=10, seed=0):
    """10-fold CV for L2-regularized polynomial regression on one feature."""
    x = X_train[:, [feature]]
    n = len(x)
    folds = np.array_split(np.random.default_rng(seed).permutation(n), k)
    cv_err = {lam: [] for lam in lambdas}
    for i in range(k):
        val = folds[i]
        trn = np.concatenate([folds[j] for j in range(k) if j != i])
        xn_trn, xn_val = normalize(x[trn], x[val])
        Phi_trn = poly_design(xn_trn, degree)
        Phi_val = poly_design(xn_val, degree)
        for lam in lambdas:
            w = fit_ridge(Phi_trn, t_train[trn], lam)
            cv_err[lam].append(rmse(Phi_val, w, t_train[val]))
    return {lam: float(np.mean(e)) for lam, e in cv_err.items()}

2. Part 2: Gaussian Basis Function

This part uses Gaussian basis functions instead of polynomials. Each basis function is centred on a randomly chosen training point $\boldsymbol{\mu}_j$, and the model is $$y(\mathbf{x}) = w_0 + \sum_{j=1}^{K} w_j \exp\left(-\frac{\|\mathbf{x} - \boldsymbol{\mu}_j\|^2}{2s^2}\right)$$ All 13 features are used. The same train/test split (first 100 / last 406 points) and the same training-set normalization as in Part 1 are used.

2.1 Setup and Method

Width. The assignment does not specify the width $s$, so I use the median heuristic: $s$ is the median Euclidean distance between pairs of (normalized) training points, which gives $s = 4.625$. It is computed from the training inputs only, was fixed before looking at any errors, and is not tuned on the test set. The results do depend on this choice: with half this width the large-$K$ test error is much smaller, and with twice this width it is much larger.

Centers. A random permutation of the training points is generated (fixed seed) and the first $K$ points are used as centers, so the centers for a smaller $K$ are a subset of those for a larger $K$. The bias $w_0$ is included. Fitting uses the same least-squares solver as Part 1 for (e) and the ridge solution $\mathbf{w} = (\Phi^T\Phi + \lambda I')^{-1}\Phi^T\mathbf{t}$ (bias not penalized) for (f). 

def median_width(X):
    """Width heuristic: median Euclidean distance between training points."""
    diff = X[:, None, :] - X[None, :, :]
    dist = np.sqrt((diff ** 2).sum(axis=2))
    return np.median(dist[np.triu_indices(len(X), k=1)])


def gaussian_design(X, centers, width):
    """Bias column, then exp(-||x - mu_j||^2 / (2 width^2)) for each center."""
    sq = ((X[:, None, :] - centers[None, :, :]) ** 2).sum(axis=2)
    return np.column_stack([np.ones(len(X)),
                            np.exp(-sq / (2 * width ** 2))])

2.2 (e) Error versus Number of Basis Functions

gaussian_regression fits $K = 5, 15, \dots, 95$ basis functions without regularization and returns the training and test RMS errors. 

def gaussian_regression(X_train, t_train, X_test, t_test,
                        ks=range(5, 100, 10), seed=0):
    """Gaussian basis regression with K random training points as centers."""
    Xn_train, Xn_test = normalize(X_train, X_test)
    width = median_width(Xn_train)
    perm = np.random.default_rng(seed).permutation(len(Xn_train))
    train_err, test_err = [], []
    for K in ks:
        centers = Xn_train[perm[:K]]         
        Phi_train = gaussian_design(Xn_train, centers, width)
        Phi_test = gaussian_design(Xn_test, centers, width)
        w = fit_ls(Phi_train, t_train)
        train_err.append(rmse(Phi_train, w, t_train))
        test_err.append(rmse(Phi_test, w, t_test))
    return list(ks), train_err, test_err, width

Comment. The training error decreases steadily as $K$ grows, from 3.57 at $K = 5$ to 0.29 at $K = 95$, since more basis functions give the model more freedom. The test error does not follow it: it stays between about 8.5 and 10.7 for every $K$ up to $85$ with no clear trend, and then jumps to 54.5 at $K = 95$. Averaging over 30 random permutations of the centers shows the underlying pattern more clearly: the median test error is lowest (8.8) for $K$ around $15$ to $25$ and then rises to 13.7 at $K = 65$ and 103 at $K = 95$, which is the usual overfitting behaviour. At $K = 95$ the model has 96 weights for 100 training points, so it nearly interpolates the training data (training RMS 0.29) and its weights become very large (the largest is about 14,936, and the bias is -69).

Two other observations. First, unlike the polynomials in Part 1, the test error never explodes to astronomical values for moderate $K$, because a Gaussian basis function is localized: for the 130 of the 406 test points that are far from every center (all basis functions below $0.001$), the prediction falls back to roughly the bias $w_0$ instead of growing without bound. This is also what drives the $K = 95$ result, since there the bias is -69, so those points are predicted around that value. Second, the test errors for moderate $K$ (about 8 to 10) are only comparable to the error of simply predicting the training mean (9.83). The first 100 towns are not representative of the rest of the dataset, so none of these models predict the test set well, and the lowest test errors are not reliably better than the constant predictor.

2.3 (f) L2-Regularized Gaussian Regression

gaussian_regression_reg fits a model with 90 basis functions for each $\lambda \in \{0, 0.01, 0.1, 1, 10, 100, 1000\}$ using all 13 features, and evaluates it with 10-fold cross-validation on the first 100 points. The points are randomly shuffled (fixed seed) into 10 folds of 10. Inside each fold, the normalization, the width $s$ and the centers are computed only from that fold's 90 training points, so no validation point is used to build the model; with 90 basis functions this means every one of those 90 points is a center. The validation RMS error is averaged over the 10 folds. 

def gaussian_regression_reg(X_train, t_train, n_basis=90, lambdas=LAMBDAS,
                            k=10, seed=0):
    """10-fold CV for L2-regularized Gaussian basis regression (all features).

    Normalization, width and centers are all computed from the training part
    of each fold only (the validation points are never used to build them).
    """
    n = len(X_train)
    rng = np.random.default_rng(seed)
    folds = np.array_split(rng.permutation(n), k)
    cv_err = {lam: [] for lam in lambdas}
    for i in range(k):
        val = folds[i]
        trn = np.concatenate([folds[j] for j in range(k) if j != i])
        Xn_trn, Xn_val = normalize(X_train[trn], X_train[val])
        width = median_width(Xn_trn)
        perm = rng.permutation(len(trn))
        centers = Xn_trn[perm[:n_basis]]
        Phi_trn = gaussian_design(Xn_trn, centers, width)
        Phi_val = gaussian_design(Xn_val, centers, width)
        for lam in lambdas:
            w = fit_ridge(Phi_trn, t_train[trn], lam)
            cv_err[lam].append(rmse(Phi_val, w, t_train[val]))
    return {lam: float(np.mean(e)) for lam, e in cv_err.items()}

Choice of $\lambda$. The validation error is lowest at $\lambda = 0.01$ (2.05) and increases steadily for larger $\lambda$, reaching 5.35 at $\lambda = 1000$, where the model is so heavily penalized that it predicts close to a constant. Without regularization the error is 12.8, about six times larger, because 90 basis functions fitted to 90 points in each fold interpolate the training data and generalize badly. I would choose $\lambda = 0.01$. This choice is stable: repeating the cross-validation with 30 different random shuffles, $\lambda = 0.01$ was the best value every time. Since 0.01 is the smallest nonzero value in the grid, an even smaller $\lambda$ might do slightly better, but it is the best of the values asked for.

One caution when comparing with part (e): the validation errors here (about 2) are much lower than the test errors in (e) (about 9). The validation folds come from the same 100 towns as the training folds, while the test set contains towns unlike any of them, so cross-validation only tells us which $\lambda$ works best within the training region, not how well the model transfers to the rest of the dataset.
